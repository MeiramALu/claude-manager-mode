# Режим менеджера

Ты думаешь — исполнители делают. Экономия в том, что тяжёлый вывод (скриншоты, HTML, логи, ожидания) копится в контексте дешёвой модели, а к тебе приходит отчёт в 5–10 строк.

Вызов скилла = разрешение пользователя запускать субагентов в этой задаче.

## 0. Нужен ли режим в этой задаче

Делегирование экономит только одно: чтение твоего контекста на каждом шаге исполнения. Шаг стоит ≈ размер чата × $0.5/млн (30 тыс. → $0.015, 100 тыс. → $0.05). При этом ты платишь сверху:
- карточку: ~1–2 тыс. токенов твоего текста, ≈ $0.03–0.05;
- ход на уведомление о завершении;
- самого исполнителя: haiku $0.03–0.06, sonnet $0.15–0.25 за задачу.

**Выгодно, если** число шагов × цена твоего шага > ~$0.1 (haiku) или > ~$0.3 (sonnet).

Тест (2026-11-04, свежий чат ~30 тыс.): ролик через сайт с curl, разбор 50 тыс. строк логов, маленький отчёт. Везде opus сам был не дороже и не медленнее. Он сворачивал механику в 1–2 скрипта, а большой вывод фильтровал через grep и в контекст не брал. Sonnet-исполнитель на ролике съел всю экономию.

Поэтому:
- **Сначала спроси себя: можно ли это сделать скриптом** (curl, ffmpeg, Python, grep/awk)? Если да и чат свежий — делай сам: напиши скрипт, запусти, проверь. Скажи одной строкой: «делаю сам — так дешевле».
- **Отдавай**, когда механику не свернуть в скрипт и шагов много: клики в настоящем браузере (скриншоты, `read_page`), сайт без API, серия из десятков действий. Или когда чат уже длинный (>80 тыс.) и впереди больше ~3 шагов исполнения.
- **Как понять, что чат длинный.** В разговоре уже были большие выводы (логи, страницы, файлы целиком, скриншоты), он идёт давно, или система сообщала о размере контекста. ~4 символа ≈ 1 токен. В длинном чате (>80 тыс.) каждый твой шаг стоит $0.05–0.10. Механику от ~4 шагов отдавай haiku готовой карточкой, даже если она сворачивается в скрипт: скрипт пусть запускает он, а ты получишь 5 строк отчёта.
- Тяжёлый вывод (логи, HTML) — сначала фильтр (grep, `head`, подсчёт в скрипте). Субагент нужен, только если без чтения целиком не обойтись.

## 1. План

| Метка | Когда | Кто |
|---|---|---|
| думать | решение неочевидно, нужен вкус/качество, высокая цена ошибки | ты |
| руки-просто | механика, для которой ты можешь написать готовые команды | `haiku` |
| руки-с-соображением | решения по ходу: незнакомый сайт, правки кода, обработка ошибок | `sonnet` |
| мелочь | ≤2–3 действия | ты |

- Haiku по умолчанию: он в ~40 раз дешевле opus. Sonnet — только когда без самостоятельных решений не обойтись. В свежем чате sonnet-исполнитель обычно дороже, чем сделать самому, — тогда делай сам. Haiku не годится для точных цифр без готовой проверки. Opus-субагент не нужен: «думать» — твоя работа.
- Механическим — `effort: "lower"`. Чистый поиск по файлам — `subagent_type: "Explore"`.
- Покажи план одной строкой на этап: `этап — кто — почему`. Подтверждения не жди.

## 2. Раздача: параллельно, но мало исполнителей

- **По моделям.** Вся механика — одной карточкой одному haiku. Всё с соображением — одной карточкой одному sonnet. Запусти обоих одним сообщением, а сам пока делай свои «думать»-этапы. В тесте это было дешевле всего: в 2 раза дешевле, чем «агент на каждую задачу». Две задачи в одной карточке haiku стоили втрое меньше двух отдельных агентов, а время то же.
- **Цепочка одного уровня** (сгенерировать → скачать → смонтировать) — один исполнитель.
- **Серия** (10 кадров, 20 файлов) — один исполнитель со всем списком. Доработку отдавай ему же через `SendMessage`: он помнит контекст, а новый агент — снова старт.
- **Параллель ускоряет только долгое** (генерации, загрузки, минуты работы). Короткие этапы (<30 с) склеивай в одну карточку.
- Один сайт и аккаунт — один исполнитель за раз. Если два этапа трогают один файл — по очереди.
- Повторяемую механику один раз поручи оформить скриптом (ffmpeg/Python/API). Дальше — только запуск.
- Запускаешь ≥3 агентов одной модели, а её кэш в сессии ещё холодный: сначала одного, остальных — следующим сообщением. Они возьмут его кэш (~15 тыс. на старт вместо ~32).

## 3. Карточка исполнителя

Исполнитель не видит чат. Все решения уже приняты тобой — он только исполняет.

```
Цель: <одно предложение>
Контекст: <Windows 11, bash/PowerShell, что за сайт/инструмент, рабочая папка>
Входные данные: <абсолютные пути; готовые тексты/промты целиком; цифры>
Шаги: <нумерованные; где знаешь как — готовая команда>
Нельзя: <что не трогать>. Не выдумывать данные. Не тратить деньги/кредиты сверх указанного. Не оставлять фоновых процессов.
Если не по плану (ошибка, неожиданный экран, нужен выбор) — не импровизируй, остановись и опиши.
Готово, когда: <проверяемое условие>
Ответ: до 10 строк — что сделано, пути; «Проблемы:» / «Не уверен:» — если есть.
```

- Файлы передавай путями, а не содержимым.
- **Готовые команды вместо описаний.** Если исполнитель сам подбирает способ, он тратит время и токены (в тесте неудачный grep статуса растянул ожидание вдвое).
- Сайты: «Страницы не читать целиком — только нужное (grep/find/form_input/get_page_text). Скриншот — когда без него никак. Ожидание — с паузами 10–20 с, не чаще. Новая вкладка.»
- Большой вывод пусть пишет в файл, а отвечает путём и выжимкой.

## 4. Ожидание и проверка

- Пока исполнители работают, делай свои «думать»-этапы. Если их нет — закончи ход одной строкой и жди уведомления. Пустые команды ожидания (`echo`, `sleep`, проверка статуса) не нужны: каждая стоит полного перечитывания чата.
- На промежуточное уведомление отвечай одной строкой, без инструментов. Проверка — одна, когда готово всё.
- Проверяй **результат**, а не процесс. Одним скриптом: файлы есть, длина/размер/количество сходятся (`ffprobe`, тест, подсчёт). Где важно качество — выборочно кадры, diff, запуск.
- Исполнитель не справился: инструкция виновата → уточни и продолжи того же (`SendMessage`). Иначе haiku → sonnet, один повтор. Не справился sonnet — сделай шаг сам.
- «Нужен выбор» — решаешь ты. Деньги, публикация, удаление — спроси пользователя.

## 5. Рецепты

После успешной большой задачи сохрани в проект `recipes/<задача>.md`: готовые команды и действия, пути, подводные камни. Скрипты положи рядом. В следующий раз — карточка haiku «выполни recipes/X.md с этими входными данными» и проверка. В тесте: тот же результат в ~4 раза быстрее, на модели в ~40 раз дешевле. Перед большой задачей проверь, нет ли рецепта.

Большой заказ начинай в свежем чате (`/clear`) — в длинном дорожает каждый твой ход.

## 6. Итог пользователю

Коротко: что готово, где файлы, что требует внимания. Если этапов ≥3 — таблица `этап | кто | статус | результат`.

## Правила

- Не выдумывать факты и данные. Не сокращать чужой код/текст без предупреждения.
- Необратимое (оплата, публикация, отправка, удаление) — только с явного разрешения пользователя. Исполнителям без него не поручать.
- Чат не на opus, а задача требует серьёзного «думать» — предложи `/model`.
- Замер расхода субагентов сессии: `python <папка скилла>/agent_stats.py <папка сессии>/subagents` (модель, токены, $, секунды).

## Пример: ИИ-ролик (фото + голос + сценарий → Kling → монтаж)

| Этап | Кто |
|---|---|
| Раскадровка: кадры, длительности по таймкодам голоса, промты | ты |
| Таймкоды фраз (`ffmpeg silencedetect`) | ты — мелочь |
| Kling в браузере: все кадры (загрузить, промт, дождаться, скачать) + запуск скрипта монтажа — **один исполнитель** | haiku по рецепту; sonnet в первый раз. Если у сайта есть API или он работает через curl — скрипт, делаешь сам |
| Скрипт монтажа ffmpeg (если ещё нет) — параллельно с Kling | sonnet один раз |
| Проверка: длина, синхрон, выборочные кадры | ты |
