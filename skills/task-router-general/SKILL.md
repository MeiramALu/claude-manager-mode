# Режим менеджера: экономия токенов в больших задачах и длинных чатах

**Главный факт.** Каждый твой ход перечитывает весь чат. Шаг стоит ≈ размер чата × $0.5/млн (opus, чтение из кэша):

| Чат | 30 тыс. | 100 тыс. | 200 тыс. |
|---|---|---|---|
| Цена одного твоего шага | $0.015 | $0.05 | $0.10 |

В длинном чате основные траты — это перечитывание, а не сама работа. Рычагов три:
1. **Меньше своих ходов**: пачки вызовов, скрипты, короткий вывод.
2. **Исполнение — в чужом контексте**: субагент работает в своём маленьком чате, а тебе приходит отчёт в 5–10 строк.
3. **Короче сам чат**: сжатие или перенос в новый чат.

Вызов скилла = разрешение пользователя запускать субагентов в этой задаче.

## 0. Оцени чат и выбери стратегию

**Как понять размер чата.** Смотри, что уже было в разговоре: большие выводы (логи, страницы, файлы целиком, скриншоты), долгая работа, сообщения системы о размере контекста. ~4 символа ≈ 1 токен. Не уверен — считай больше, а не меньше.

| Чат | Стратегия |
|---|---|
| Свежий (< ~40 тыс.) | Делай сам: исполнитель стоит дороже, чем твои шаги. Субагенты — только для клика в настоящем браузере (скриншоты), десятков шагов, которые не свернуть в скрипт, или чтения огромных материалов целиком. |
| Средний (40–100 тыс.) | Механику от ~6 шагов — haiku одной карточкой. Остальное сам, с рычагами из §1. |
| Длинный (> ~100 тыс.) | Ты только думаешь, решаешь и проверяешь. Любое исполнение от ~3–4 шагов — исполнителям. Если впереди ещё много работы, предложи сжать чат (§2). |

**Цена делегирования:**
- карточка ≈ 1–2 тыс. твоего текста ($0.03–0.05);
- ход на уведомление о завершении (одна цена шага);
- сам исполнитель: haiku $0.03–0.06, sonnet $0.15–0.25.

Выгодно, если шагов исполнения × цена твоего шага больше этой суммы.

Замеры (2026-11-04):
- **Свежий чат.** Ролик через сайт, разбор 48 тыс. строк логов, маленький отчёт — opus сам был не дороже. Он сворачивал механику в скрипты и фильтровал вывод через grep.
- **Длинный чат (~200 тыс.).** Тот же ролик с исполнителем стоил $2.36 против $4.18 (−43%) за то же время.

## 1. Рычаги без субагентов — всегда

- **Независимые вызовы — одним сообщением.** Это один ход вместо N, и чат перечитывается один раз.
- **Скрипт вместо серии команд.** Цикл, обработку 20 файлов, проверку из 5 пунктов — одним скриптом и одним запуском.
- **Короткий вывод.** `grep`/`head`/`wc`, тихие флаги, подсчёт в скрипте вместо распечатки. Читай нужную часть файла, а не весь. Большой вывод пиши в файл и смотри выжимку. Всё, что попало в чат, ты будешь перечитывать до конца разговора.
- **Не перечитывай** то, что уже есть в контексте, и не проверяй одно и то же дважды.
- **Короткие ответы пользователю** — длинный текст тоже ложится в историю.

## 2. Сжатие длинного чата

**Автоматический режим (плагин с хуками).** Если в контексте появляются сообщения «Размер чата сейчас ≈ N тыс.», значит работает хук-контролёр:
- Размер из его сообщения — это и есть размер чата для таблицы §0.
- Когда он пишет, что приближается автосжатие, на ближайшей паузе между этапами обнови `.claude/handoff.md` (до 60 строк):
  ```
  # Цель
  # Сделано (с путями к файлам)
  # Решения и почему
  # Следующий шаг
  # Подводные камни / что не трогать
  ```
- Claude Code сожмёт чат сам. Хук вернёт этот файл в контекст, и работа продолжится без участия пользователя.
- Когда задача закончена, удали или очисти `handoff.md`, чтобы он не всплывал в следующих чатах.

**Без хуков.** Если чат > ~150 тыс. и впереди ещё несколько этапов, сжатие экономит больше всего остального. Между этапами (не посреди) предложи пользователю один из двух вариантов:
- **`/compact`** — Claude Code сожмёт историю в выжимку. Быстро, но детали могут потеряться.
- **Передача в новый чат.** Запиши в `handoff.md`: цель, что сделано, принятые решения, пути к файлам, следующий шаг, подводные камни. Пользователь делает `/clear` и пишет «продолжи по handoff.md». Новый чат стартует с ~5 тыс. вместо 150 тыс., и каждый ход дешевле в 10–30 раз.

Решает пользователь — предложи одной строкой, с прикидкой выгоды.

## 3. План и раздача

| Метка | Когда | Кто |
|---|---|---|
| думать | решение неочевидно, нужен вкус/качество, высокая цена ошибки | ты |
| руки-просто | механика, для которой ты можешь написать готовые команды | `haiku` |
| руки-с-соображением | решения по ходу: незнакомый сайт или код, правки по описанию, обработка ошибок | `sonnet` |
| мелочь | ≤2–3 действия | ты |

**Выбор модели**
- Haiku по умолчанию: в ~40 раз дешевле opus.
- Sonnet — только если без самостоятельных решений не обойтись. В свежем чате он обычно дороже, чем сделать самому.
- Haiku не годится для точных цифр без готовой проверки.
- Opus-субагент не нужен: «думать» — твоя работа.
- **Тип исполнителя.** Команды, скрипты, файлы — `subagent_type: "task-router-general:worker"`. Поиск в сети — `"task-router-general:web-worker"`. Они стартуют с ~11 тыс. токенов, а general-purpose — с ~20 тыс. По умолчанию это haiku; для «руки-с-соображением» передай `model: "sonnet"`. Браузер (MCP) — через general-purpose. Если этих типов нет, бери general-purpose.
- Механическим исполнителям — `effort: "lower"`. Поиск по коду или файлам с выводами вместо дампов — `subagent_type: "Explore"`.

**Как раздавать**
- **По моделям.** Вся механика — одной карточкой одному haiku, всё с соображением — одной карточкой одному sonnet. Запусти обоих одним сообщением и делай пока свои «думать»-этапы. Две задачи в одной карточке haiku стоили втрое меньше двух агентов, а время то же.
- **Мало исполнителей.** Каждый — это старт 11–32 тыс. токенов плюс твой ход на уведомление. Цепочку одного уровня и серию однотипных шагов отдавай одному исполнителю. Доработку — ему же через `SendMessage`: он помнит контекст.
- **Параллель ускоряет только долгое** (сборки, генерации, загрузки, большие поиски). Короткие этапы склеивай.
- **Конфликты.** Один сайт и аккаунт — один исполнитель. Если два этапа трогают один файл — по очереди.
- **Повторяемое — скриптом.** Один раз поручи написать скрипт, дальше только запуск.
- **≥3 агентов одной модели при холодном кэше** — сначала одного, остальных следующим сообщением: возьмут кэш, старт ~15 тыс. вместо ~32.

Покажи план одной строкой на этап (`этап — кто — почему`) и не жди подтверждения.

## 4. Карточка исполнителя

Исполнитель не видит чат. Все решения уже приняты тобой.

```
Цель: <одно предложение>
Контекст: <ОС/оболочка, проект/сайт/инструмент, рабочая папка>
Входные данные: <абсолютные пути; готовые тексты/промты целиком; цифры>
Шаги: <нумерованные; где знаешь как — готовая команда>
Нельзя: <что не трогать>. Не выдумывать данные. Не тратить деньги/кредиты сверх указанного. Не оставлять фоновых процессов.
Если не по плану (ошибка, неожиданный экран, нужен выбор) — не импровизируй, остановись и опиши.
Готово, когда: <проверяемое условие>
Ответ: до 10 строк — что сделано, пути; «Проблемы:» / «Не уверен:» — если есть.
```

- Файлы передавай путями, а не содержимым. **Готовые команды вместо описаний**: исполнитель, который сам подбирает способ, тратит время и токены.
- Большой вывод (найденные строки, выжимки, логи) пусть пишет в файл, а отвечает путём и главным.
- Сайты: «Страницы целиком не читать — только нужное (grep/find/form_input/get_page_text). Скриншот — когда без него никак. Ожидание — паузы 10–20 с. Новая вкладка.»

## 5. Ожидание и проверка

- Пока исполнители работают, делай свои «думать»-этапы. Если их нет — закончи ход одной строкой. Пустые команды ожидания (`echo`, `sleep`, опрос статуса) не нужны: каждая — полное перечитывание чата.
- На промежуточное уведомление — одна строка, без инструментов. Проверка одна, когда готово всё.
- Проверяй **результат**, а не процесс, одним скриптом: файлы есть, тесты прошли, числа и количество сходятся. Где важно качество — выборочно: diff, запуск, фрагменты.
- Исполнитель не справился:
  1. Виновата инструкция — уточни и продолжи того же (`SendMessage`).
  2. Иначе haiku → sonnet, один повтор.
  3. Не справился sonnet — сделай шаг сам.
- «Нужен выбор» — решаешь ты. Деньги, публикация, удаление — спроси пользователя.

## 6. Рецепты

После успешной повторяемой задачи сохрани в проект `recipes/<задача>.md`: готовые команды, пути, подводные камни. Скрипты положи рядом. В следующий раз — карточка haiku «выполни recipes/X.md с этими входными данными» и проверка. В замере: в ~4 раза быстрее, на модели в ~40 раз дешевле. Перед большой задачей проверь, нет ли рецепта.

## 7. Итог пользователю

Коротко: что готово, где файлы, что требует внимания. Если этапов ≥3 — таблица `этап | кто | статус | результат`.

## Правила

- Не выдумывать факты и данные. Не сокращать чужой код/текст без предупреждения.
- Необратимое (оплата, публикация, отправка, удаление, push) — только с явного разрешения пользователя. Исполнителям без него не поручать.
- Чат не на opus, а задача требует серьёзного «думать» — предложи `/model`.
- Замер расхода субагентов сессии: `python <папка скилла>/agent_stats.py <папка сессии>/subagents`.

## Как раздавать разные задачи (длинный чат)

| Задача | Ты (думать) | Исполнители |
|---|---|---|
| Фича или рефакторинг в коде | план, интерфейсы, ключевые решения, ревью diff | sonnet: правки по плану; haiku: тесты, линтер, массовые переименования |
| Баг, разбор логов | гипотезы, вывод, решение | Explore/haiku: найти и выжать нужные строки в файл, вернуть 10 строк |
| Поиск по большому проекту | что ищем и зачем | Explore: «где и как устроено X» — выводы, а не дампы файлов |
| Исследование, сравнение (веб/документы) | вопросы, критерии, итоговый вывод | haiku/sonnet: по исполнителю на тему, выжимки с источниками в файлы |
| Данные, таблицы, отчёты | что считать, проверка цифр | haiku: скрипт по готовой формуле, запуск, файл результата |
| Тексты и документы | структура, тон, финальная редактура | sonnet: черновики разделов по плану |
| Браузер: сайты, кабинеты, формы, генерации (Kling и т.п.) | промты, решения, проверка | haiku по рецепту; sonnet — в первый раз. Есть API/curl — скрипт |
| Файлы и администрирование | что и где менять | haiku: команды по списку, отчёт |
| Видео/аудио-монтаж | раскадровка, тайминг | haiku: генерации/загрузки по рецепту; sonnet: скрипт ffmpeg один раз |
